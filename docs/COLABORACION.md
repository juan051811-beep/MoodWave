## Trabajo en GitHub

1. El propietario del repositorio invita a la cuenta de GitHub del otro integrante desde **Settings → Collaborators**.
2. Cada integrante configura su propio `git config user.name` y `git config user.email` para que sus commits se atribuyan correctamente.
3. Se recomienda trabajar con ramas por función, crear pull requests y revisar los cambios antes de incorporarlos a `main`.
4. El reconocimiento en el README **no sustituye** el historial real de commits y contribuciones de GitHub.

## Convención sugerida de commits

- `docs: documentar arquitectura y algoritmos`
- `fix: corregir cálculo de estadísticas`
- `feat: agregar funcionalidad de calendario`
- `test: añadir pruebas del motor de pasos`

No se debe fabricar una autoría histórica mediante fechas o firmas de commits que no correspondan a quienes realmente hicieron los cambios.
